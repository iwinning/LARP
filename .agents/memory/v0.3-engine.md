# v0.3 Qualified-Count Engine

## The rule
`_run_scrape_job` chases `qualified_count` (persons that pass all filters), NOT raw `scanned_count`. The early-stop signal flows from app.py → scrapa_alla.py via the `on_page` callback.

**Why:** Users set a target like "500 people with phone + villa". Raw scanned count is useless for that goal — only qualified count matters.

**How to apply:** Any feature that touches progress reporting or stopping conditions must read `g["qualified"]`, not `g["scanned"]`.

## on_page callback contract
- `hamta_personer(..., on_page=fn)` calls `fn(sida_persons: list[dict])` after each page.
- Return `True` → continue scraping. Return `False` → break inner loop and stop this area.
- `sida_persons` contains raw dicts with `namn/telefon/adress/alder/stad/kalla` — already deduped within-area by scrapa_alla.py.
- app.py's `make_on_page` does cross-area dedup (global_dedup set), postal-code filtering, and quality filtering inside the callback.

## Global state dict `g`
Keys: `scanned`, `qualified`, `duplicate`, `rejected`. All mutated inside `on_page` closure. Using a dict (not plain vars) avoids `nonlocal` in nested closures.

## Distribution modes
- `target`: All areas share the same pool. Stop globally when `g["qualified"] >= target_count`.
- `balanced`: Each area gets a soft quota (`target // n_areas`, remainder distributed). Deficit from exhausted areas is redistributed to remaining pending areas.
- `exhaust`: No global target. Each area runs until no more pages. `hard_scan_budget` = 200 000.

## Hard scan budget
`max(target * 20, 2000)`, capped at 200 000 (or 200 000 for exhaust). Prevents infinite loops when the filter rate is unexpectedly low.

## Regex gotcha: \b vs (?!\w)
The personnummer regex ends with `(?!\w)` NOT `\b`. Word boundary `\b` fails after `****` (asterisk is not a word char), causing age extraction to silently return "" for masked personnumbers. Always use `(?!\w)` at the end of personnummer-like patterns.
