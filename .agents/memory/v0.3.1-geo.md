## Rule
`_run_scrape_job` takes `areas: list[dict]` (not `stader: list[str]`). Every caller must
normalise inputs with `_normalize_area(raw)` before passing them. Raw can be a string like
"16850 Bromma" or a dict `{postal_code, city}`.

**Why:** Merinfo returns results from wrong locations when searching only by postal code (e.g.
"168 50" matches Västerås and Täby). Combining postal + city in the search string and then
validating the actual address against the requested area eliminates false positives.

## How to apply
- `/scrape` endpoint: parse `data.get("areas")` (new format) or legacy `stader` strings,
  normalise with `_normalize_area`, pass `areas` list to `_run_scrape_job`.
- `_run_scheduled_job`: normalise `schedule["stader"]` strings the same way.
- Progress SSE and done payload both include `wrong_location_count`.
- CSV fieldnames include `postal_code`.
- `_validate_geography(result, area)` is skipped when `area["postal_code"] == ""` (pure
  city search — legacy behaviour preserved).
- All 45 tests in `test_core.py` + `test_geo_validation.py` must pass (45 green).

## Key functions (app.py)
- `_extract_postal_code(address)` → 5-digit string or ""
- `_normalize_area(raw)` → `{postal_code, city, _display, _search}`
- `_validate_geography(result, area)` → `(bool, reason)` where reason ∈
  `{"", "wrong_postal_code", "wrong_location"}`
