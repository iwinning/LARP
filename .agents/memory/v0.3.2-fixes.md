## Rules

### 1. City source of truth
`_person_to_result` NEVER uses `p["stad"]` as verified city. It always extracts city
from the actual scraped address via `_extrahera_ort_fran_adress(adress)`.
`scrapa_alla.py` saves `"stad": ""` and `"search_location": stad` so the search query
is preserved for debugging but cannot contaminate geo-validation.

**Why:** `stad` in the person dict is the Merinfo search query (e.g. "168 50 Bromma"),
not a verified city. Using it as city caused correct Bromma results to be geo-rejected.

### 2. Balanced mode — finish current page on local quota hit
When balanced local quota is reached mid-page, the engine sets `quota_hit_this_page=True`
but does NOT `return False` inside the person loop. It returns False only after
`emit_progress()` at the end of the page. Global target still returns False immediately.

**Why:** Breaking mid-page silently discarded persons 6-10 when quota hit at person 5.
If area B was thin, those lost persons could never be recovered even on revisit.

### 3. Per-area budget ceiling (motor level)
Inside `on_page`, after `ast_["scanned"] += 1`, there is a check:
`if ast_["scanned"] > area_budget: stop`. This applies to all modes.

**Why:** Guarantees no area exceeds its allocated scan budget regardless of provider behaviour.

### 4. Backend postal code validation
In `/scrape` endpoint, after normalizing areas: any area with a non-empty `postal_code`
that doesn't match `^\d{5}$` returns 400 with Swedish error message.

### 5. UI resetProgress fix
`resetProgress()` now includes `'statWrongLocation'` in the reset list.
