# VIKTIG BETYDELSE AV `target_count`

`target_count` betyder:

> hur många UNIKA personer som uppfyller ALLA aktiva filter jag vill ha som slutresultat.

Det betyder INTE:

> hur många profiler som ska kontrolleras.

Exempel:

```text

Krav:
✓ Telefonnummer
✓ Villa
✓ Ålder 30–65
```

```text

Duplicates          44
Without phone      317
Wrong housing      201
Wrong age          181
Qualified          500
```

Det är korrekt.

Jobbet ska stoppa när:

```python
qualified_count == target_count
```

inte när:

```python
scanned_count == target_count
```

# DEL 2 — FIXA AGE EXTRACTION HELT

Nuvarande `_extrahera_alder()` är nästan klar men behöver även stöd för:

```text
19981023
```

utan maskerade sista fyra siffror.

Stöd minst:

```text
27 år
19981023
19981023-****
19981023-XXXX
1998-10-23
```

Prioritet:

### 1. Explicit ålder

```text
27 år
```

### 2. Fullt födelsedatum

```text
19981023
19981023-****
19981023-XXXX
1998-10-23
```

Beräkna riktig ålder med år, månad och dag.

Exempel:

```python
age = today.year - birth_date.year

if (today.month, today.day) < (birth_date.month, birth_date.day):
    age -= 1
```

### Viktigt

Regexen får INTE tolka:

* telefonnummer
* postnummer
* slumpmässiga nummer

som födelsedatum.

Validera datum med riktig datumparsing.

Spara endast:

```text
age
```

Lagra inte maskerat personnummer permanent.

# DEL 3 — STOPPA EXAKT PÅ TARGET

Nuvarande implementation kan överskjuta target eftersom en hel resultatsida processas innan stoppkontroll sker.

Exempel på fel:

```text
Target: 500

Qualified före sida:
490

Nästa sida innehåller:
25 kvalificerade

Nuvarande resultat:
515
```

Det är fel.

Slutresultatet ska vara:

```text
500
```

---

# IMPLEMENTATION

Target-kontrollen måste ske **inne i personloopen**.

Princip:

```python
for person in page_results:

    if target_reached():
        break

    process_person(person)
```

Efter att en person kvalificerat:

```python
qualified_count += 1
```

kontrollera om målet nåtts.

När:

```python
qualified_count >= target_count
```

ska inga fler personer läggas till.

Resultatlistans längd ska aldrig överskrida `target_count` i:

* `balanced`
* `target`

# DEL 4 — HARD SCAN BUDGET FÅR ALDRIG ÖVERSKRIDAS

Hard scan budget finns redan, men den kan idag överskridas av en hel resultatsida.

Exempel:

```text
Budget = 2000
```

ska aldrig kunna ge:

```text
Scanned = 2100
```

---

# FIX

Kontrollera budgeten inne i personloopen.

Princip:

```python
if scanned_count >= hard_scan_budget:
    stop
```

innan nästa person räknas.

Krav:

```text
scanned_count <= hard_scan_budget
```

alltid.

---

# TA BORT FELAKTIG MINIMUM-BUDGET

Om nuvarande kod innehåller något i stil med:

```python
remaining_budget = max(
    hard_scan_budget - scanned_count,
    100
)
```

ändra detta.

Om endast 23 scans återstår ska motorn inte begära minst 100.

Använd:

```python
remaining_budget = hard_scan_budget - scanned_count
```

och:

```python
if remaining_budget <= 0:
    stop
```

# DEL 5 — HARD SCAN BUDGET SKA ANPASSAS TILL VALFRITT TARGET

Eftersom användaren nu kan skriva valfritt target måste safety budget räknas dynamiskt.

Exempel på rimlig princip:

```python
hard_scan_budget = target_count * 20
```

med:

```text
minimum
+
absolute maximum
```

Exempel:

```python
hard_scan_budget = max(target_count * 20, 2000)
hard_scan_budget = min(hard_scan_budget, SAFE_ABSOLUTE_MAX)
```

Behåll nuvarande värden om de redan är rimliga.

Poängen är:

```text
Target 37
```

och:

```text
Target 5000
```

ska inte använda exakt samma scan-budget.

# DEL 7 — SKILJ `quota_reached` FRÅN `exhausted`

Detta är nödvändigt för Balanced.

Ett område som gjort:

```text
100 / 100
```

är INTE automatiskt:

```text
exhausted
```

Det kan fortfarande finnas 300 fler personer där.

Inför eller använd separata statuses:

```text
pending
running
quota_reached
exhausted
target_reached
budget_reached
error
completed
```

### `quota_reached`

Betyder:

> området fyllde sin nuvarande fairness-kvot men kan ha fler resultat.

### `exhausted`

Betyder:

> datakällan har faktiskt inga fler nya användbara resultat för området.

Detta måste vara separata states både i backendlogiken och frontendvisningen.
