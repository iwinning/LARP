# PROBLEMET

Per-area budget finns redan, exempelvis:

```python
EXHAUST_BUDGET_PER_AREA = 50_000
```

Men den nuvarande kontrollen ligger efter att räknarna har ökats.

Implementation motsvarar ungefär:

```python
g["scanned"] += 1
ast_["scanned"] += 1

if ast_["scanned"] > area_budget:
    return False
```

Det skapar ett off-by-one-fel.

Med:

```text
Area budget = 50 000
```

kan området nå:

```text
50 001 scanned
```

innan det stoppas.

Det ska vara omöjligt.

---

# FIX

Kontrollera area-budgeten **innan nästa person räknas som scanned**.

Princip:

```python
if ast_["scanned"] >= area_budget:
    stop_reason_area[0] = "budget"
    return False

g["scanned"] += 1
ast_["scanned"] += 1
```

Anpassa variabelnamn efter befintlig implementation.

Kravet är:

```text
area_scanned <= area_budget
```

alltid.

Inte:

```text
area_scanned <= area_budget + 1
```

# GLOBAL BUDGET SKA FORTSATT FUNGERA

Behåll den befintliga globala safety-budgeten.

Ordningen bör i princip vara:

```python
if global_budget_reached:
    stop_job

if area_budget_reached:
    stop_area

process_next_person
```

Så ingen counter ökas efter att respektive budget redan nåtts.

---

# EXHAUST MODE

I `exhaust` ska varje område fortfarande få sin egen budget.

Exempel:

```text
Area A budget = 50 000
Area B budget = 50 000
Area C budget = 50 000
```

Om A försöker leverera 60 000 kandidater:

```text
A scanned = 50 000
```

sedan ska motorn fortsätta till B.

A får inte konsumera B:s area-budget.

---

# KRITISKT REGRESSIONSTEST

Det nuvarande testet med endast ett område kan maskera buggen eftersom global budget och area-budget kan nås samtidigt.

Lägg därför till ett test med **minst två områden**.

## Scenario

```text
Distribution:
exhaust

Per-area budget:
50 000

Area A:
60 000 kandidater

Area B:
10 kandidater
```

Expected:

```text
A scanned = 50 000
B scanned = 10
```

Och:

```text
A scanned <= 50 000
B scanned <= 50 000
```

Globalt:

```text
Total scanned = 50 010
```

förutsatt att den globala safety-budgeten tillåter det.

Testet ska misslyckas om:

```text
A scanned = 50 001
```

---

# TESTA ÄVEN EXAKT BUDGETGRÄNS

Lägg till eller verifiera scenario:

```text
Area budget = 50 000
Area contains exactly 50 000 candidates
```

Expected:

```text
scanned = 50 000
```

Alla 50 000 får processas.

Den 50 001:a får inte processas.

# STATUS

När ett område stoppas på sin area-budget ska status/reason vara tydlig, exempelvis:

```text
budget_reached
```

eller befintlig motsvarande status.

Det får inte felaktigt märkas:

```text
exhausted
```

om orsaken egentligen var budgeten.

Skillnaden ska behållas:

```text
exhausted
= inga fler resultat finns

budget_reached
= det kan finnas fler resultat men safety-budgeten nåddes
```
